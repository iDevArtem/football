# app/services — Слой сервисов и фоновых задач

Модуль объединяет бизнес-логику рендеринга сообщений карточки игры для Telegram и фоновое периодическое выполнение задач с помощью `APScheduler`.

---

## 📁 Структура

- `render.py` — функции форматирования HTML-сообщений для Telegram: карточка игры, списки участников, статус оплат.
- `scheduler.py` — настройка фонового планировщика (`AsyncIOScheduler`) и задача автоматического открытия друзей `open_friends_job`.

---

## 🎨 Рендеринг карточки игры (`render.py`)

Telegram Bot API требует валидной разметки сообщений (в проекте используется `parse_mode="HTML"`).

### 1. Защита от поломки верстки (`html.escape`)
> [!IMPORTANT]
> Любой пользовательский ввод (`game['title']`, `participant['display_name']`, `cancel_reason`) обязан экранироваться через `html.escape()`.
> Если имя игрока содержит символы `<`, `>`, `&` без экранирования, Telegram вернет ошибку `can't parse entities` и сообщение не будет отправлено.

### 2. Функция `format_game_message()`
Формирует единую карточку игры со следующими секциями:
- Заголовок с префиксом (`⚽ ` для активной игры или `❌ ` для отмененной).
- Текущий статус игры (`status_text()`).
- Дата, время, длительность (мин и ч).
- Динамический статус формата матча (`dynamic_format_text()`: 5х5, с заменами, 3 команды, полный сбор).
- Ставка аренды поля (в режиме записи — ставка за час, в режиме оплаты — общая аренда за сыгранные часы и цена с человека).
- Счетчик основного состава (`confirmed / max_players`) и резерва (`reserve`).
- Нумерованный список основного состава (с отметкой `👥` для друзей и `•` для основных игроков).
- При статусе `payment_collection` напротив каждого игрока отображается отметка оплаты (`✅ оплатил`, `🚫 не играл`, `❌ не оплатил`) и сводка оплат.
- Список резерва (если есть).
- Количество отказавшихся (`declined`).
*(Строки о статусе друзей удалены из текста сообщения для чистоты карточки; кнопки добавления друзей появляются на клавиатуре при их доступности).*

## ⏱ Фоновый планировщик (`scheduler.py`)

Бот использует `apscheduler.schedulers.asyncio.AsyncIOScheduler` для периодических проверок в фоновом режиме.

### Задача `open_friends_job(bot)`
- **Периодичность**: запускается каждые 5 минут (`interval`, `minutes=5`, `max_instances=1`).
- **Алгоритм**:
  1. Выбирает все игры, у которых `friends_allowed: False`, статус `registration_open` и наступило время `friends_allowed_after <= now`.
  2. Проверяет количество игроков в основном составе (`confirmed`).
  3. Если основной состав уже полон (`confirmed_count >= max_players`), друзья не открываются.
  4. Если места есть:
     - Вызывает `game_repo.open_friends(game_id)`.
     - Заново получает актуальный состав участников.
     - Обновляет сообщение в Telegram-группе через `bot.edit_message_text()` с клавиатурой, содержащей кнопки добавления и отмены друга.

### Жизненный цикл
Планировщик запускается в `app/main.py` через `setup_scheduler(bot)` и корректно останавливается при завершении работы бота через `scheduler.shutdown(wait=False)`.
