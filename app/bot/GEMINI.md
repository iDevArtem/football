# app/bot — Telegram-интерфейс и обработчики (aiogram 3)

Модуль отвечает за взаимодействие с пользователями и администраторами в Telegram: обработка slash-команд, inline-кнопок, FSM-сценариев, генерация клавиатур и маршрутизация сообщений.

---

## 📁 Структура

- `handlers.py` — маршруты, FSM-состояния, валидация прав, логика обработки команд и callback-запросов.
- `keyboards.py` — функции-фабрики генерации inline-клавиатур (`InlineKeyboardMarkup`).

---

## 🔑 Ключевые компоненты и архитектурные решения

### 1. Маршрутизация и разделение чатов (Группа vs Личка)
- **Создание игры (`/new_game`)**:
  - Строго проверяется `is_group_chat(message)` и `is_admin(message.from_user.id)`.
  - При создании исходная команда админа немедленно удаляется через `delete_message_safely()`.
  - Создается единственное закрепляемое/главное сообщение матча с кнопками.
- **Тихое администрирование (`Silent Admin UX`)**:
  - Нажатие кнопки `⚙️ Управление` или команда `/game_settings` отправляет клавиатуру управления **в личные сообщения админу** (`send_private_admin_menu()`).
  - Все изменения (дата, цена, лимит игроков, статус) транслируются в группу через обновление главного сообщения игры `update_game_message()`.
  - Никаких админских диалогов и служебных сообщений в общем чате группы!

### 2. Решение проблемы FSM между чатами
Aiogram привязывает FSM-состояние к связке `(chat_id, user_id)`.
- Если пользователь нажимает кнопку «Добавить друга» в групповом чате, а имя друга должен ввести в личке с ботом, стандартный FSM может сбиться.
- **Решение**: используется оперативный in-memory словарь `PENDING_FRIEND_INPUTS: dict[int, dict]`, индексированный по `user_id`.
- Аналогично, `PENDING_PRIVATE_ACTIONS` запоминает намерение пользователя, если бот еще не имеет права писать ему в личку (пользователь сначала должен отправить `/start` боту).

### 3. Ограничение Telegram на размер `callback_data` (64 байта)
> [!CAUTION]
> Telegram Bot API строго ограничивает длину строки `callback_data` ровно 64 байтами.

- Строка вида `pay:<game_id>:<participant_id>:paid` превышает 64 байта, так как `ObjectId` занимает 24 символа (24 + 24 + префиксы > 50-60 байт, с риском переполнения).
- **Паттерн сокращения в проекте**:
  - Для оплаты друзей используется `pf:<participant_id>:p` (где `p` = paid, `n` = not_played).
  - Сам `game_id` извлекается из документа участника в MongoDB.

### 4. Префиксы Callback-запросов

| Префикс | Назначение | Пример |
|---|---|---|
| `game:<game_id>:join` | Запись игрока («Буду») | `game:64a...:join` |
| `game:<game_id>:decline` | Отказ игрока («Не буду») | `game:64a...:decline` |
| `game:<game_id>:add_friend` | Запрос на добавление друга | `game:64a...:add_friend` |
| `game:<game_id>:cancel_friend` | Запрос на отмену своего друга | `game:64a...:cancel_friend` |
| `admin:<game_id>:broadcast_menu` | Меню рассылки по группам | `admin:64a...:broadcast_menu` |
| `admin:<game_id>:pub:<chat_id>` | Публикация карточки в группу | `admin:64a...:pub:-100123...` |
| `admin:<game_id>:unpub:<chat_id>` | Отзыв карточки из группы | `admin:64a...:unpub:-100123...` |
| `admin:<game_id>:pub_all` | Публикация во всех группах | `admin:64a...:pub_all` |
| `admin:<game_id>:*` | Действия админского меню | `admin:64a...:settings` |
| `friend:<game_id>:<friend_id>:cancel` | Отмена конкретного друга | `friend:64a...:64b...:cancel` |
| `pay:<game_id>:paid` | Игрок подтверждает свою оплату | `pay:64a...:paid` |
| `pay:<game_id>:not_played` | Игрок отмечает, что не играл | `pay:64a...:not_played` |
| `pay:<game_id>:friends` | Открытие меню оплаты друзей | `pay:64a...:friends` |
| `pf:<participant_id>:<action>` | Оплата/пропуск конкретного друга | `pf:64b...:p` |
| `pfc:<game_id>` | Закрыть меню оплаты друзей | `pfc:64a...` |
| `noop` | Неактивная кнопка (заголовок/индикатор) | `noop` |

## 🛡 Безопасность и обработка исключений

1. **`TelegramBadRequest`**:
   - При вызове `bot.edit_message_text()` обязательно оборачивать в `try...except TelegramBadRequest`, так как Telegram возвращает ошибку `message is not modified`, если текст и клавиатура не изменились.
   - При вызове `message.delete()` обязательно перехватывать ошибку на случай, если сообщение уже удалено или у бота нет прав.
2. **`TelegramForbiddenError`**:
   - Возникает, если пользователь заблокировал бота или ни разу не нажимал `/start` в личке.
   - Обрабатывать через `send_private_message()` и информировать пользователя в группе временным самоуничтожающимся сообщением (`temporary_reply`).
