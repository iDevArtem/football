# Правила разработки Telegram-бота на aiogram 3

Этот набор правил обязателен к соблюдению при модификации или добавлении функциональности в модули `app/bot` и взаимодействия с Telegram Bot API.

---

## 1. Лимит на длину `callback_data` (Строго до 64 байт)

- В спецификации Telegram Bot API параметр `callback_data` в `InlineKeyboardButton` имеет жесткое ограничение: **максимум 64 байта**.
- `ObjectId` в MongoDB занимает 24 hex-символа. Если попытаться передать два ID (например, `game_id` и `participant_id`), строка `pay:64a8b...:64a8c...:status` в сумме с двоеточиями и статусом превышает 64 байта и вызывает фатальную ошибку `BUTTON_DATA_INVALID`.
- **Правило**:
  - Всегда минимизируйте префиксы и количество параметров в callback_data.
  - Если нужно оперировать объектом, передавайте только один `participant_id` (например, `pf:<participant_id>:p`), а связанные сущности (`game_id`, `chat_id`) извлекайте из базы данных в теле хэндлера.

---

## 2. Паттерн «Тихий админ» (Silent Admin UX)

- Все взаимодействия администратора (редактирование даты, цены, лимитов, закрытие записи, отмена) должны происходить **в личных сообщениях** с ботом.
- В общем чате группы должно находиться **только одно** интерактивное сообщение карточки игры.
- Исходные сообщения с командами `/new_game`, `/game_settings`, `/cancel_game` и т.д. должны немедленно удаляться ботом.
- При изменении любых параметров вызывайте `update_game_message()`, чтобы актуализировать текст и кнопки в группе.

---

## 3. Обработка ограничений на инициацию сообщений в ЛС

- Telegram API запрещает боту первым отправлять сообщения пользователю, если тот ни разу не открывал диалог с ботом и не отправлял `/start`.
- При вызове `send_private_message()` обязательно перехватывайте `TelegramForbiddenError` и `TelegramBadRequest`.
- Если бот не может отправить сообщение пользователю в ЛС:
  1. Сохраните отложенное действие в `PENDING_PRIVATE_ACTIONS[user_id]`.
  2. Покажите пользователю временное самоуничтожающееся сообщение (`temporary_reply`) в группе с просьбой нажать `/start` в личке бота.

---

## 4. Межчатовые FSM-сценарии

- Стандартный FSM-контекст aiogram привязан к паре `(chat_id, user_id)`.
- Если сценарий начался в группе (нажатие inline-кнопки), а ввод данных (например, имя друга) продолжается в личных сообщениях, используйте оперативный словарь `PENDING_FRIEND_INPUTS[user_id]`.
- После завершения или отмены сценария всегда очищайте запись из словаря (`PENDING_FRIEND_INPUTS.pop(user_id, None)`) и удаляйте сервисные сообщения prompt через `cleanup_friend_input()`.

---

## 5. Экранирование HTML в сообщениях

- Все динамические данные (имена игроков, никнеймы, названия игр, причины отмены) перед вставкой в шаблон сообщения обязаны экранироваться через `html.escape()`.
- Никогда не конкатенируйте неэкранированный пользовательский ввод в строки с `parse_mode="HTML"`.

---

## 6. Безопасное редактирование и удаление сообщений

- Telegram API выбрасывает `TelegramBadRequest: message is not modified`, если текст сообщения и разметка не изменились. Любой вызов `edit_message_text` обязан оборачиваться в `try...except TelegramBadRequest: pass`.
- Удаление сообщений всегда выполняйте через функцию `delete_message_safely(message)`, подавляя ошибку, если сообщение уже удалено пользователем.
