# Football Telegram Bot — Архитектурная подсказка и правила проекта

Проект представляет собой асинхронный Telegram-бот на Python (aiogram 3 + MongoDB) для организации футбольных матчей в групповых чатах с поддержкой основного состава, автоматического резерва, механизма приглашения друзей, учета оплат и скрытого администрирования через личные сообщения.

---

## 🛠 Технологический стек

- **Python 3.12** (venv в `.venv`)
- **aiogram 3.13.1**: асинхронный фреймворк для Telegram Bot API (Router, FSM, Inline-клавиатуры).
- **MongoDB + PyMongo 4.10.1 (`AsyncMongoClient`)**: асинхронный драйвер для работы с базой данных.
- **APScheduler 3.10.4**: планировщик фоновых задач (периодическое открытие добавления друзей).
- **Pydantic 2.9.2 & pydantic-settings 2.6.1**: типизированная конфигурация из `.env`.
- **Docker & Docker Compose**: контейнеризация бота и MongoDB 8.0.

## 🧠 Ключевые бизнес-правила и особенности домена

1. **Создание и рассылка игры (ЛС или группа)**:
   - Команда `/new_game` может выполняться **в личных сообщениях с ботом** или в группе **только администратором** (`ADMIN_TELEGRAM_IDS`).
   - Короткий формат: `/new_game YYYY-MM-DD HH:MM` (например, `/new_game 2026-11-06 19:00`) с дефолтами (лимит 15 чел, аренда 600 грн/час, 90 мин, открытие друзей через 6 ч). Расширенный формат из 8 аргументов также поддерживается.
   - При создании в ЛС бот формирует карточку и предлагает меню выбора целевых групп (`📢 Опубликовать во всех` или по отдельности).
   - При создании в группе сообщение с командой удаляется, а карточка публикуется в этом чате.
   - Любое изменение карточки мгновенно и параллельно транслируется во все привязанные группы игры через `update_game_message()`.

2. **Вместимость, очередь и динамический формат**:
   - Лимит игроков: по умолчанию 15 (верхняя планка для 3 команд по 5 человек).
   - Динамический статус формата в карточке: до 9 чел (сбор), 10 чел (2 команды 5х5), 11–12 чел (5х5 с заменами), 13–14 чел (3 команды с ротацией), 15 чел (3 команды 5х5).
   - Очередность строго определяется полем `position` (автоинкремент). Первые 15 — основа (`confirmed`), 16+ — резерв (`reserve`).
   - При отказе игрока (`decline_player`) первый из резерва автоматически продвигается в основу.

3. **Правила добавления друзей**:
   - Добавление друзей изначально заблокировано.
   - Друзья открываются автоматически по таймеру `friends_open_after_hours` (если состав не полон) либо вручную админом.
   - В карточке игры текст о статусе друзей не отображается, чтобы не захламлять сообщение; кнопки `➕ Добавить друга` / `➖ Отменить друга` появляются автоматически при открытии набора.
   - Лимит: максимум 3 друга от одного участника (`count_friends_by_user`).
   - Имя друга вводится **в личке с ботом**, с поддержкой бесшовного отложенного ввода после `/start`.

4. **Тихое администрирование (Silent Admin UX)**:
   - Кнопка `⚙️ Управление` в группе доступна только админам.
   - По нажатию бот присылает меню управления **в личные сообщения админу**.
   - Все изменения (дата, цена, состав, закрытие записи, отмена) обновляют единое главное сообщение игры в группе через `update_game_message()`.

5. **Оплата матча (`payment_collection`) и деление аренды поля**:
   - При старте сбора оплат админ выбирает в ЛС фактическую длительность матча (`⏱ 1.5 часа (900 грн)` или `⏱ 2.0 часа (1200 грн)` исходя из ставки 600 грн/час).
   - Бот автоматически делит общую сумму аренды на всех подтвержденных участников основы (`ceil(total / count)`) и выставляет точную цену с человека.
   - Участник может подтвердить оплату или статус `не играл` для себя и своих друзей.
   - Админ имеет право переопределять статусы оплаты любого участника.

## ⚠️ Критические технические ограничения

- **Ограничение `callback_data` Telegram (64 байта)**:
  - Никогда не упаковывай в `callback_data` длинные составные идентификаторы (например, `game_id` + `participant_id` + `action`).
  - Используй короткие префиксы (например, `pf:<participant_id>:p` для оплаты друга). `game_id` извлекается из документа участника в БД.
- **Взаимодействие в личке (Private Chat Initiation)**:
  - Telegram запрещает боту первым писать пользователю в ЛС, если пользователь никогда не отправлял боту `/start`.
  - Для этого есть словарь `PENDING_PRIVATE_ACTIONS` и проверка с уведомлением пользователя.
- **FSM-состояния между чатами**:
  - В aiogram FSM привязан к `(chat_id, user_id)`. Переход группа -> личка может сломать FSM.
  - Поэтому межчатовые состояния хранятся в `PENDING_FRIEND_INPUTS` по `user_id`.

## 🚀 Команды разработки и запуска

- **Запуск через Docker Compose**:
  ```bash
  docker compose up --build
  ```
- **Локальный запуск (с локальной MongoDB)**:
  ```bash
  ./.venv/bin/python -m app.main
  ```
- **Проверка синтаксиса и импортов**:
  ```bash
  ./.venv/bin/python -c "import app.main; print('OK')"
  ```
